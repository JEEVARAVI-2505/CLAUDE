11. Repository Structure and Approval Records

Figma holds the master design. The repository holds documents, approved exports, evidence and tokens. Use this structure for every project (project ID in the repo name, for example vel-ux-2026-001-clientname). Do not copy confidential client assets into the repository unless the contract allows it.

ui-ux-project/
├── README.md  CHANGELOG.md
├── docs/            project-overview, design-brief, requirements, competitor-research,
│                    user-personas, user-journey, sitemap, design-decisions,
│                    accessibility, handoff, qa-report (.md)
├── research/        references/ competitor-analysis/ user-interviews/ usability-tests/ findings/
├── design-system/   foundations/ (colours, typography, spacing, grid .md)
│                    components/ patterns/ design-tokens/
├── wireframes/      desktop/ tablet/ mobile/
├── ui-design/       desktop/ tablet/ mobile/ light-theme/ dark-theme/
├── prototypes/
├── assets/          images/ icons/ illustrations/ exports/
├── testing/         usability/ accessibility/ visual-qa/
├── handoff/         specifications/ assets/ developer-notes/
└── delivery/        final-approval.md  delivery-checklist.md

Git conventions

  • Branches: main (approved only), draft/<topic> for work in progress. Never commit passwords, API keys or client personal data.
  • Commit messages: G3: add mobile wireframes v02 (gate or stage, then what).
  • Update CHANGELOG.md with every approved version; tag releases v1.0-G6.
