Cloud Platform Engineering (AWS First)

Teaching order: master AWS first (Level 5, about 4 weeks). Introduce Azure and GCP afterwards through comparative exercises (“build the same 3-tier app on Azure; what is the equivalent of a Security Group?”). Do not teach three clouds at once.

The 10-question template for every cloud service

For each service the trainee writes a one-page sheet answering: 1 What is it? 2 Why does it exist? 3 When to use? 4 When not to use? 5 How is it priced? 6 How to configure? 7 How to secure? 8 How to monitor? 9 How to troubleshoot? 10 What are the alternatives?

Worked example: reference 3-tier AWS architecture

Users→Route 53 DNS→ALB + ACM cert (public subnets)→App on EC2/ECS (private subnets)→RDS (isolated subnets)
  • Network: one VPC, two Availability Zones, public / private-app / private-data subnets, NAT Gateway for outbound updates, S3 gateway endpoint.
  • Security: ALB SG allows 443 from the internet; app SG allows only from ALB SG; DB SG allows 5432 only from app SG. No public DB IP.
  • Data: RDS encrypted at rest, automated backups, Multi-AZ if the availability target requires it.
  • Ops: CloudWatch alarms, CloudTrail enabled, AWS Backup plan, budget alert.
Cost awarenessNAT Gateways, load balancers, Multi-AZ databases, data transfer out and idle resources are common surprise costs. Always use the provider's official pricing calculator and record region, date and assumptions (Stage 05).

Tool pack (what every tool lesson must contain)

Installation → setup → configuration → commands → folder structure → use cases → assignment → troubleshooting. Examples of the first and most important:

Git & GitHub

git config --global user.name "Your Name"
git config --global user.email "you@company.com"
git switch -c feature/add-health-check
git add . && git commit -m "feat: add /health endpoint"
git push -u origin feature/add-health-check

Then open a Pull Request. Troubleshoot: merge conflicts, wrong branch, committed a secret (rotate it immediately; history rewrite is not enough).

Docker

docker build -t app:1.0 .
docker run -d -p 8080:8080 --name app app:1.0
docker logs app
docker ps

Troubleshoot: container exits (check docker logs); port already in use; no space (docker system df).

Terraform / OpenTofu

terraform fmt -recursive
terraform init
terraform validate
terraform plan -out=tfplan
terraform apply tfplan

Troubleshoot: state lock, drift, provider auth errors. Always read the plan.

Security scanners

gitleaks detect --source .
trivy fs .
trivy image app:1.0

Fail the pipeline on critical findings; triage the rest with owners and dates.
