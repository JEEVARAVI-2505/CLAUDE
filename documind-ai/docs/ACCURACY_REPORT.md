## Read this first

* **Synthetic data only.** Fictional invoices from `documind.samples` in 7 layouts. The generator and the extractor were written by the same team, so these numbers are an *upper bound for look-alike documents*. They are **not** an estimate of accuracy on your customers' real documents, which will be lower and must be measured on a customer sample (see ACCEPTANCE_TESTS.md).
* **Rules-only mode.** No AI model was available in the build environment, so the Ollama path was tested only against a protocol stub. No AI accuracy is claimed.
* Scans were produced by drawing the same text with a clean bitmap font then applying the listed degradation; real scanner noise, stamps, handwriting, logos, tables with ruling lines and multi-column layouts are not represented.
* Metric: exact string match of the normalised value. Precision = correct / (correct + wrong values produced). Recall = correct / (fields that exist). A field whose truth is absent and which was not produced is not counted.

## Known limitations

* Scores depend on layout vocabulary in `resources/rules/labels_default.json`; unseen vocabularies need templates (Professional package).
* Dates like 03/04/2025 are *flagged* as ambiguous rather than counted as errors; the benchmark resolves them with the configured day-first default.
* Sample size is small (see counts) so differences of a few percent are not meaningful.
